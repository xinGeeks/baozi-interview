# 手动 Smoke 验收清单

> 本文档**不**在 CI 中跑(需要真实 API key)。开发者手动启动 Streamlit,按以下步骤验收。

## 启动

```bash
# 1. 配 API key
cp .env.example .env
# 编辑 .env,填入 LLM_API_KEY

# 2. 装依赖
pip install -r requirements.txt

# 3. 启动
streamlit run app.py
```

浏览器打开 http://localhost:8501。

## Smoke 流程(社招中级 + 压力)

### 准备
- 一份 PDF 简历(可用自己的或 `tests/fixtures/sample_resume.pdf`)
- 一段 JD 文本(可用 `tests/fixtures/sample_jd.txt` 或真实岗位 JD)

### 步骤

1. **侧边栏**:
   - 上传 PDF 简历,确认显示 `✅ 简历解析完成 (N 字)`
   - 选 **社招(中级)**
   - 选 **压力深挖**

2. **主区**:
   - 粘贴 JD 到 text_area
   - 点 **🚀 开始面试**

3. **对话**:
   - 应当立刻出现第一题(自我介绍类开场)
   - 输入回答,提交
   - 观察追问是否有针对性(应紧扣简历项目或 JD 技能)
   - 答 5 轮(根据时间)
   - 在某次回答中带 **结束面试** 关键词,或点 **🛑 结束面试并出报告**

4. **报告**:
   - 应当自动渲染六维报告
   - 检查每项打分是否附了**具体依据**(引用候选人原话)
   - 检查打分是否有**区分度**(不全 7-8)
   - 检查是否包含「下一阶段练习重点」(不是「录用建议」)
   - 点 **💾 下载报告** 验证导出

## 验收 Checklist

打开报告时,逐项确认:

### 报告结构(必含)
- [ ] 基础信息段(岗位、等级、复盘评级)
- [ ] 六维度打分(岗位匹配 / 专业技术 / 项目实战 / 逻辑思维 / 沟通表达 / 职级适配)
- [ ] 候选人核心优势(2-4 条,具体引用)
- [ ] 核心短板(2-4 条,具体引用)
- [ ] 针对性提升建议(分技术 / 项目 / 话术 / 职级 4 类)
- [ ] 下一阶段练习重点(不是录用建议)

### 质量(必查)
- [ ] **不全是 7-8 分**——如果六维全在 7-9,说明 prompt 没约束住,需调 `prompts.py` 报告段
- [ ] **每分附依据**——如果「打分依据」是空话(如『基础扎实』),需调
- [ ] **优势引用具体回答**——不能是『基础扎实、综合表现良好』
- [ ] **短板可改**——不能只贴标签,要有『下次可以怎么答』
- [ ] **拒绝套话**——不出现『具有一定潜力』『综合表现良好』

### 对话流畅性(必查)
- [ ] AI 一次只问一题(不出现『请介绍...然后再说说...』)
- [ ] AI 顺着候选人回答追问(不按死板题库)
- [ ] 压力风格时,AI 适度质疑(不凶也不软)
- [ ] 温和风格时,AI 引导补充(不空洞鼓励)
- [ ] 候选人简历中提到的项目,被 AI 至少问 1 次

## 6 档 × 2 风格 = 12 组合验收(发布前必跑)

每个组合各跑一次简短对话(3-5 轮),目视检查:

| 职级 | 温和 | 压力 |
|---|---|---|
| 校招 | [ ] 偏基础/潜力 | [ ] 偏基础+稍质疑 |
| 实习 | [ ] 偏工具/上手 | [ ] 偏工具+稍质疑 |
| 社招(初级) | [ ] 偏基础实操 | [ ] 偏基础+深挖 |
| 社招(中级) | [ ] 偏项目+选型 | [ ] 偏项目+质疑 |
| 社招(高级) | [ ] 偏架构+方案 | [ ] 偏架构+压 |
| 社招(资深) | [ ] 偏体系+规划 | [ ] 偏体系+压 |

**关键不变量**:校招不考架构题,资深不能只聊基础。

## 异常路径(发布前必跑)

- [ ] **没填 JD 直接点开始** → 应当提示"请先粘贴 JD"
- [ ] **上传非 PDF** → 应当提示"无法识别为 PDF"
- [ ] **上传加密 PDF** → 应当提示"PDF 已加密"
- [ ] **上传扫描件 PDF** → 应当提示"未抽取出任何文本"
- [ ] **断网状态下点开始** → 应当提示"LLM 调用失败:网络超时"
- [ ] **输入含"结束面试"** → 自动停问,生成报告

## 修复指南

如果验收失败,先看 `app.py` / `prompts.py` 改动:
- 报告打分虚高 → 调 `build_report_prompt` 的"不全是 7-8"约束
- AI 一次问多题 → 强化 `SINGLE_QUESTION_RULE`
- AI 越级提问 → 在 `build_interviewer_system_prompt` 强调"不越级"
- 报告全是套话 → 强化 `NO_HONEYMOON` / 优势短板必须引用

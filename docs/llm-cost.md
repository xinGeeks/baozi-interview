# LLM 成本估算

> v0.3 alpha-kickoff · 估算口径,精度 ±25%

## 估算方法

- **公式**:`tokens ≈ len(text) // 4`(每 4 字符约 1 token)
- **来源**:`cost.estimate_tokens()` 实现
- **精度**:中文 1 字符 ≈ 0.5-1 token,英文 1 字符 ≈ 0.25 token;±25% 误差
- **更准的方法**:用 `tiktoken` 库(本工具**不引入**,避免 +5MB 安装包)

## 单场面试成本估算(5 轮)

> 假设:简历 2000 字 / JD 800 字 / 5 轮问答每轮回答 300 字 / 报告生成 2k token

| 阶段 | 输入 token | 输出 token | 合计(估算) |
|---|---|---|---|
| 简历 + JD 上下文 | ~700 | - | 700 |
| 5 轮面试(每轮一问一答) | ~5 × 800 = 4,000 | ~5 × 200 = 1,000 | 5,000 |
| 5 轮逐轮反馈 | ~5 × 1,000 = 5,000 | ~5 × 150 = 750 | 5,750 |
| 报告生成 | ~6,000 | ~2,000 | 8,000 |
| **单场总计** | **~15,700** | **~3,750** | **~19,500** |

## 每日预算指引

- **轻度自测**:1-3 场/日 → `LLM_DAILY_TOKEN_CAP=100000`(~1 美元)
- **正式 alpha**:5-10 场/日 → 默认 `LLM_DAILY_TOKEN_CAP=200000`(~2 美元)
- **团队共享**:50+ 场/日 → `LLM_DAILY_TOKEN_CAP=2000000`(~20 美元)
- **不限**:重置为 `0`,关闭预算检查

## 实际成本核算

> 当前实现只用 `len(text) // 4` 估算,**不是真实成本**。真实 usage 要
> 等 LLM 平台账单或 API 响应的 `usage` 字段。v0.4 会用 `response.usage`
> 替换为真实计数(目前 streaming 模式下需要额外解析)。

## 误判与调优

如果 UI 提前熔断但你感觉还有余量:

1. 查 `.env` 中 `LLM_DAILY_TOKEN_CAP` 当前值
2. 提高到 1.5-2 倍(实际估算比 char/4 略高,中文长 prompt 可能偏估多)
3. 重启 streamlit 让 `get_daily_token_cap()` 重新读 env

如果 UI 一直不警告但月底账单超支:

1. 平台计费口径可能含 image / tool use / 缓存等(本工具不估这些)
2. 考虑 v0.4 引入 tiktoken 或平台 usage 字段做更精准核算
